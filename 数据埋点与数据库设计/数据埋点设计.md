# 数据埋点设计

> 文档状态：当前有效
> 设计版本：V1.0
> 建立日期：2026-07-29
> 确认日期：2026-07-29
> 范围：43 个页面、10 个页面族状态机、179 个唯一转换、MVP 主链与 Sprint 6 预留

## 1. 目标与边界

埋点用于回答：用户是否完成有效工作、AI 是否稳定地产生可用候选、版本变化是否带来可复核改善。埋点不替代业务表、审计、服务日志或用户确认。

### 1.1 MVP 采集

- 核心业务事实：创建、保存、提交、通过、退回、确认、失败、跳过、派生和归档。
- AI 事实：任务、调用、上下文、结果、检查、采用、修改、拒绝、取消、过期和重试。
- 关键前端行为：页面进入、关键动作发起、候选审核、恢复/重试、放弃未保存内容、版本比较。
- 数据质量：事件缺失、重复、迟到、Schema 拒收、关联失败和补偿。
- 版本归因：产品发布、Project Version、Skill/Prompt/Template/Context Strategy/Model 实际版本。

### 1.2 MVP 不采集

- 鼠标轨迹、热图、逐次按键、剪贴板内容、全量点击流。
- 页面停留时长和虚构的 AI 百分比进度。
- 完整文档正文、文件正文、Prompt 全文、敏感上下文、密钥或凭据。
- 未采用 AI 输出全文；只保留摘要、指纹、质量、原因和必要追溯。
- 仅由视图渲染推导、不能改变决策的状态切换。

### 1.3 增强预留

- Sprint 6：知识候选、审核、检索、注入、引用、采用和索引质量。
- Future：受控实验分流、自动评测和保留清理作业；未获批不采集、不建表。

## 2. 事件分层

| 代码 | 类型 | 权威生产者 | 存储 | 使用规则 |
|---|---|---|---|---|
| `BF` | 服务端业务事实 | Business API | 业务表 + Business Outbox + `behavior_event` | 事务成功后产生；失败必须是确定失败 |
| `AI` | AI 运行事实 | AI Service/Worker | AI 表 + AI Outbox + `behavior_event` | Task/Call/Result 分层；重试不覆盖旧调用 |
| `UI` | 有决策价值的前端行为 | Web，经 Business API 接收 | `behavior_event` | 只记录意图/恢复/放弃等；不得冒充业务成功 |
| `AU` | 安全与关键操作审计 | Business API | `operation_audit_log`，必要时同时出 BF | 权限、认证、确认、归档、版本命令必须审计 |
| `NC` | 不新增采集 | — | — | 已有事实可推导、纯渲染或无决策价值 |

同一动作允许产生一条 BF 和一条 AU，但不得由前端再产生同名成功事件。例如“设置工作版本”由前端记录 `ui.action_started`，最终成功只由服务端产生 `project_version.working_set`。

## 3. 公共事件契约

### 3.1 命名

`<domain>.<entity>.<past_fact>`，全小写，单词使用下划线；`schema_version` 单独版本化，不把 `v1` 写进名称。

示例：

- `project.version_derived`
- `review.feedback_deferred`
- `ai.call_failed`
- `ui.unsaved_changes_discarded`

### 3.2 公共信封

所有事件至少遵守《数据字典》的公共信封。字段规则：

- `event_id` 全局唯一；生产者重试必须复用同一 ID。
- `occurred_at` 是事实时间，`ingested_at` 是接收时间；不得互换。
- `result_status=failed` 时 `failure_code` 必填。
- 业务事实必须尽可能带 `project_id`、`project_version_id`、对象和版本。
- AI 事件必须带 `ai_task_id`；Call 级事实必须带 `ai_call_id`。
- 用户提交类事件带 `command_id`；由其他事件触发时带 `causation_id`。
- `payload_json` 只保存本事件专属结构化字段，不复制公共字段。

### 3.3 兼容与幂等

- 只追加可选字段属于兼容变更；删除、改名、改变语义或必填性必须提升 `schema_version` 并提供迁移期。
- Event Consumer 以 `event_id` 唯一去重；重复投递不重复计数。
- 迟到事件按 `occurred_at` 回填开放窗口；超过窗口标记 late，并触发受影响指标重算或不可用说明。
- 错误事实通过 `event_compensation` 修正，原事件保持不可变。

## 4. 触发时机总则

| 场景 | 正确触发时机 | 禁止做法 |
|---|---|---|
| 创建/提交/确认 | 数据库事务提交成功后写 Outbox | 点击按钮即记成功 |
| 确定失败 | 服务端返回稳定失败码后 | 网络断开即猜测业务失败 |
| AI 阶段 | AI 状态持久化后 | 仅根据前端动画推断 |
| 文件上传 | 元数据和对象存储状态一致后记完成 | 只收到 HTTP 200 即记完成 |
| 候选采用 | 正式版本创建和 Adoption 同事务成功后 | `ready` 即记采用 |
| 页面进入 | 权限检查和页面上下文解析成功后 | 路由开始就记成功到达 |
| 取消 | 服务端确认取消完成后记 AI/业务取消；点击取消仅记 UI 意图 | 点击后立即改写最终状态 |
| 重试 | 新尝试/新 Call/新任务创建成功后 | 覆盖原失败记录 |
| 归档/恢复 | 业务事务成功后，同时写审计 | 只隐藏页面卡片 |

## 8. 用户行为表与业务数据库关系

`behavior_event` 与业务表是“分析引用”，不是第二事实源：

- `object_type/object_id/object_version_id` 指向当时对象；允许对象归档，不允许事件随对象删除。
- 业务成功事件必须能通过 `trace_id/command_id` 与业务写入、审计和 Outbox 对齐。
- 多态对象引用每天运行关联质量检查；无法关联的事件标记 unusable，不进入指标。
- 页面事件允许没有 `object_id`，但必须有 `page_id`、`module` 和 `session_id`。
- 业务状态重建只能读取业务表和版本谱系，不能通过行为事件回放重建。

## 9. 数据质量门禁

| 规则 | 门槛 | 处置 |
|---|---:|---|
| 核心事件公共字段完整率 | ≥99% | 未达标的事件/指标标记 unusable |
| AI 正式结果追溯完整率 | 100% | 不允许正式化或宣称可复现 |
| 重复业务事件率 | <0.5% | 暂停受影响指标的版本判断 |
| 业务对象关联成功率 | ≥99% | 失败样本进入质量 Issue |
| Schema 拒收率 | 监控，无虚设业务目标 | 阻断生产者破坏性发布 |
| 迟到事件 | 单独展示数量与影响窗口 | 重算或披露不完整，不静默忽略 |
| 分母为零 | 返回 N/A | 禁止返回 0% |

## 10. 数据分析后台需求（增强）

### 10.1 页面与能力

| 能力 | 主要内容 | 默认访问 |
|---|---|---|
| 数据健康 | 字段完整、重复、迟到、拒收、关联失败、受影响指标 | admin |
| 核心流程 | Project Version cohort、阶段到达/通过/周期、返轮和 Issue 去向 | admin；owner 仅项目范围 |
| AI 运行 | Task/Call 成功、首次成功、重试、P50/P95、Token、成本、错误类型 | admin |
| AI 质量 | 结构、完整、追溯、采用、大改、拒绝、重大错误、抽样维度 | admin；owner 仅项目范围 |
| 版本优化 | 产品发布、Project Version、AI Capability Version 的前后比较 | admin；owner 仅项目范围 |
| 知识运营 | 候选审核、检索、注入、引用、采用和陈旧资产（S6） | admin/知识审核者 |
| 样本下钻 | 从指标定位去敏后的事件、任务、调用、对象版本和 trace | 按原业务权限二次校验 |
| 口径管理 | Metric ID、版本、公式、过滤、责任人、变更记录 | admin 只读；修改走受控流程 |

### 10.2 交互与过滤

- 全局过滤：时间窗、产品发布、Project、Project Version、任务类型、模块、AI 能力版本、数据质量状态。
- 比率同时显示分子、分母和样本量；时延显示 P50/P75/P95，不只显示均值。
- 指标卡必须显示口径版本、最近计算时间、数据质量状态和受影响说明。
- Drill-down 不展示密钥、原始凭证、完整敏感上下文和无权正文。
- 导出包含过滤、口径版本、生成时间和数据质量说明；导出本身写审计。
- MVP 不建设上述 UI；以固定 SQL/离线报表完成数据验收，且不新增一级导航。
