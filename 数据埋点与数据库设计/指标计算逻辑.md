> 文档状态：当前有效
> 口径版本：V1.0
> 建立日期：2026-07-29
> 确认日期：2026-07-29
> 权威关系：本文件实现《数据指标体系》《AI质量评价指标》《版本优化指标》；VO 编号以专项《版本优化指标》为准

## 1. 统一计算规则

### 1.1 事实、时间与样本

- 默认事实源为业务表、AI 追溯表和通过质量门禁的 `behavior_event`；UI 点击不得替代业务成功。
- 时间使用 `occurred_at` 或业务事实的提交时间；`ingested_at` 只用于迟到监控。
- 默认排除测试账号、内部压测、已补偿原事件、Schema 拒收、重复事件和 `quality_status=unusable` 的数据。
- 比率分母为 0 时返回 `N/A`；同时保存分子、分母和样本量。
- 项目流程同时提供创建 cohort 和完成时间视图，禁止把跨周期完成全部归到创建日而不说明。
- AI 指标至少按 `task_type` 分层；版本对比还需按项目阶段、复杂度和输入完整度分层。
- P50/P75/P95 使用最近秩方法或数据库等价实现，并在 `metric_definition` 固定算法版本。

### 1.2 事件去重、迟到和补偿

1. 先按 `event_id` 去重。
2. 排除存在有效 `event_compensation` 且补偿类型为 void 的原事件；replace 类型使用替代载荷。
3. 日指标允许 T+2 回填，周指标允许 T+7；超过开放窗口的迟到事件触发重算申请或披露缺口。
4. 同一业务动作的 UI/BF 不相加；成功指标只取 BF 或权威业务表。
5. 同一 AI Task 的多次 Call 分开计算调用指标，Task 指标只去重 `ai_task_id`。

### 1.3 数据质量门禁

| 门禁 | 规则 |
|---|---|
| 核心事件完整率 | `<99%` 时受影响业务指标 `unusable` |
| AI 正式结果追溯 | 非 100% 时不得计算“可复现正式结果”或宣称版本有效 |
| 重复业务事件率 | `>=0.5%` 时受影响窗口不可用于版本结论 |
| 关联失败 | 样本不能定位到权威对象/版本时从正式分子分母排除，并披露排除量 |
| 小样本 | 不虚设统一阈值；低于优化记录的 `minimum_sample` 时结论为证据不足 |

## 3. 优化结论规则

| 结论 | 条件 | 数据动作 |
|---|---|---|
| `improved` | 主指标达到事前最小改善，所有护栏在容忍区间，质量通过 | 计入 VO-06 分子 |
| `no_material_change` | 数据充分，主指标未达到最小改善，护栏稳定 | 不计改善，保留证据 |
| `worsened` | 主指标恶化或任一关键护栏越界 | 进入回退/降级评估 |
| `insufficient_evidence` | 样本不足、质量失败、口径变化、严重失衡或组合变更不可拆分 | 计入 VO-07，不得宣称有效 |

同一优化只能有一个主指标；允许 1～2 个驱动和 1～2 个护栏。目标和容忍区间必须在观察前写入 `optimization_evaluation`。

## 4. 指标生产与刷新

| 节奏 | 指标 | 产物 |
|---|---|---|
| 每日 | AR-02/03/06/07/08/09/12、AQ-08、事件质量 | 运行查询、告警、DQ Issue |
| 每周 | NS、KPI-01/02、PU、AQ-01～08、KA-05 | 固定离线报表与样本下钻 |
| 每次发布/观察窗结束 | KPI-03、VO-01～09 | 版本评价记录 |
| 每月 | AQ-09/10、KA、长期趋势与口径审查 | 指标字典复核建议 |

MVP 不要求持久化所有 `metric_snapshot`；允许固定、版本化查询直接生成报表。但每个查询必须输出 metric_id/version、窗口、过滤、分子、分母、样本量、质量状态和计算时间。

## 5. 可执行血验规则

### 5.1 指标到数据

- NS/KPI-01 必须定位到每个 Project Version 的七段正式证据。
- KPI-02/AQ-04～07 必须定位到 AI Result 与当前 Adoption 结论。
- AR 必须从 AI Task/Call/Context 计算，禁止从前端进度消息计算。
- PU-07～12 必须读取 Review、Difference、Round、Test、Issue 权威表，不仅依赖事件。
- VO 必须读取同一 `metric_version` 的前后结果；口径不同直接判证据不足。

### 5.2 样本下钻

每个 Snapshot 保存或可重建：

- 纳入和排除规则。
- 去敏后的样本业务 ID/Task ID 查询条件。
- 数据质量 Issue。
- 产品发布、Project Version、AI Capability Version。
- 查询版本或 Commit 引用（实施阶段补充）。

## 6. VO 口径变更说明

原《数据指标体系》使用 VO-01～07，并从 VO-03 开始与专项《版本优化指标》错位。本次统一为专项 VO-01～09：

| 原通用口径 | 新唯一口径 |
|---|---|
| 原 VO-03 主指标相对变化 | VO-04 相对变化；新增 VO-03 绝对变化 |
| 原 VO-04 护栏恶化数 | VO-05 |
| 原 VO-05 版本改善率 | VO-06 |
| 原 VO-06 结论不确定率 | VO-07 |
| 原 VO-07 优化生效周期 | VO-08 |
| 未登记 | VO-09 回退率 |

历史报表必须带 `metric_version`；旧编号结果不得与 V1.0 新口径直接拼接。
