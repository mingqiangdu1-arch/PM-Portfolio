# 验收标准

> 文档状态：当前有效（2026-07-29 已确认）
> 规划版本：V1.0
> 建立日期：2026-07-29
> 适用范围：Sprint 验收、MVP 发布、私有部署与 Sprint 6 增强验收

## 1. 验收原则

1. 以当前有效产品、交互、页面状态机和 UI 基线为业务与体验依据。
2. 以 OpenAPI、数据库迁移、事件 Schema 和 Provider Contract 为技术证据。
3. 每项验收必须保存可复现证据：自动化报告、查询、日志、trace、截图或演示步骤。
4. 成功路径、失败路径、权限路径、并发路径和恢复路径均需验收。
5. 不以模拟数据、静态页面或口头说明代替可运行闭环。
6. 用户确认是 AI 候选成为正式产物、阶段规划升格和发布的必要门禁。

## 2. 全局 Definition of Done

功能只有同时满足以下条件才算完成：

- 对应任务、代码审查和测试全部完成。
- OpenAPI/Schema、数据库迁移、事件字典和运行文档已同步。
- 页面正常、加载、空数据、失败、权限、只读、冲突和恢复状态符合基线。
- 写操作具备权限、幂等、并发和审计保护。
- 业务事实、AI 追溯和必要事件可按 `trace_id` 关联。
- 无新增未处置 Critical/High 安全问题。
- 降级路径经过验证，不产生虚假成功或覆盖历史。

## 4. 端到端验收 T01～T07

### T01 从零完成项目版本

步骤：注册/登录 → 创建项目/V1 → Requirement → PRD → Design Review → Implementation Plan → Confirmation Round → Test Record → 无 Issue 完成或创建 Issue。

通过条件：

- 每个正式对象可定位 Project Version、来源、状态和当前有效版本。
- AI 输出均经过人工确认。
- 阶段门禁不可绕过；失败恢复后不会重复生成正式事实。

### T02 携带已有资料接续

步骤：创建/选择项目 → 导入资料 → 解析 → 选择起始节点 → 处理缺失门禁 → 进入目标工作台。

通过条件：解析失败、部分结果、手动指定、风险接受和权限不足均有独立状态；原文件始终保留。

### T03 AI 生成、审核与保存

步骤：配置任务 → 排队/生成/检查 → 离页 → 任务中心恢复 → 候选审核 → 修改后采用 → 保存正式版本。

通过条件：失败、取消、质量阻断和目标过期可区分；重试保留原调用记录；ready 不等于正式保存。

### T04 设计评审循环

步骤：发起评审 → 提交反馈 → 处置 → 阻断返回修改 → 新产物版本 → 再次评审 → 通过。

通过条件：评审快照不可变；反馈有处理去向；无权限、提交失败和并发冲突不改变旧结论。

### T05 实现确认

步骤：创建确认轮次 → 关联实现资料 → 记录差异 → 就绪检查 → 使轮次有效。

通过条件：阻断差异不能通过；多轮历史可查；提交失败不撤销旧有效轮次。

### T06 验证与迭代

步骤：创建/执行 Test Record → 提交结果 → 创建 Issue → 分类 → 选择当前修正/派生/暂缓/拒绝。

通过条件：Issue 归属正确；处置可审计；派生新版本不覆盖历史。

### T07 历史查看与安全派生

步骤：查看版本谱系 → 打开历史只读 → 可选比较 → 基于历史派生。

通过条件：查看历史不改变当前工作版本；派生是新业务事实；并发冲突安全处理。

## 6. API 与数据验收

### 6.1 API

- 所有正式接口位于 `/api/v1` 并进入 OpenAPI。
- ID 对外为字符串，时间为 UTC RFC 3339。
- 响应包含 `code/message/data/trace_id`；错误包含安全的 `details`。
- 列表游标稳定，不因同页新增数据产生重复/遗漏。
- 创建/命令支持 `Idempotency-Key`；同 Key 不同请求体返回冲突。
- 可变对象使用 `expected_version`；冲突返回 409 和最新版本引用。
- 越权不泄露敏感正文、来源摘要、密钥或对象内部细节。

### 6.2 数据库与迁移

- 空库、已有上一版本数据和失败重试三种迁移场景通过。
- 外键、唯一约束、复合索引、归档和不可变规则与 ER 一致。
- 迁移前预检空间、版本和锁风险；迁移后运行一致性查询。
- 不使用删除历史事实来实现回滚；业务回滚通过新版本或补偿记录。

### 6.3 数据质量

| ID | 门槛 |
|---|---|
| AC-DATA-01 | AI 正式结果追溯完整率 100% |
| AC-DATA-02 | 核心事件必填字段完整率 ≥99% |
| AC-DATA-03 | 重复业务事件率 <0.5% |
| AC-DATA-04 | 每个指标样本可定位，公式、时间窗、过滤和口径版本明确 |
| AC-DATA-05 | 分母为零显示 N/A；样本不足/无基线不下改善结论 |
| AC-DATA-06 | 分析明细不复制密钥、凭证或默认复制完整敏感上下文 |

| ID | 门槛 |
|---|---|
| AC-NFR-01 | 非 AI API P95 ≤500ms，测试错误率 <1% |

## 8. 发布 Gate

### 8.1 MVP 必须全部满足

- Sprint 0～5 的 P0 任务完成。
- `AC-S0～AC-S5`、T01～T07、API/数据/NFR/安全/无障碍/运维门槛通过。
- 无阻断产品冲突、Critical/High 缺陷或不可恢复数据风险。
- Flow 按 Gate 完整启用或安全关闭；不得以半完成状态上线。
- 生产配置、迁移、备份、恢复、告警和回滚责任人明确。
- 用户对发布候选和已知限制完成最终确认。

### 8.2 允许带入后续版本

- Sprint 6 知识中心、Qdrant RAG、多 Provider。
- 完整分析看板、自动评测和运营工作台。
- 正式 SVG/PNG 设计文件包等不阻断前端实现的补交付物。
- 不影响主链、安全、数据完整性和可恢复性的 P2 缺陷。

### 8.3 不允许豁免

- 历史覆盖、越权、密钥泄露、不可恢复迁移。
- AI 候选自动成为正式产物。
- AI 正式结果追溯不完整。
- T01～T07 任一路径存在死路。
- 备份不可恢复或无回滚方案。
- 通过隐藏入口掩盖仍可被 API 调用的未完成功能。

## 9. 验收记录模板

每次 Sprint/发布验收至少记录：

- 验收版本、Commit、镜像和数据库迁移版本。
- 环境、日期、参与人和责任人。
- 覆盖的任务 ID 与验收 ID。
- 自动化报告和人工演示证据位置。
- 缺陷、风险、降级和残留事项。
- 结论：通过、条件通过或不通过。
- 条件通过的截止时间、责任人和复验结果。
