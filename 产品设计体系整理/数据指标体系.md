# 数据指标体系

> 文档状态：当前有效  
> 基线版本：V1.0  
> 生效日期：2026-07-27  
> 适用范围：平台使用、AI 运行、AI 输出质量、知识资产和版本优化指标

## 1. 指标框架

### 1.1 北极星指标

**有效闭环项目版本数（NS-01）**：统计周期内完成 Requirement → PRD → Review → Implementation Plan → Confirmation Round → Test Record → Issue 处置或“无 Issue”结论，并且关键证据可追溯的项目版本数。

该指标代表平台交付的真实闭环价值；单纯生成文档、调用 AI 或创建项目不计入。

### 1.2 三个主 KPI

| ID | 指标 | 公式 | 用途 | MVP |
|---|---|---|---|---|
| KPI-01 | 薄闭环完成率 | 有效闭环项目版本数 / 进入需求确认的项目版本数 | 判断核心流程能否被完成 | 是 |
| KPI-02 | AI 有效采用率 | `adopted + adopted_after_edit` 的已评审 AI 任务数 / 已评审 AI 任务数 | 判断 AI 是否产生实际可用结果 | 是 |
| KPI-03 | 版本改善率 | 主指标改善且全部护栏未显著恶化的已评估优化数 / 已完成评估优化数 | 判断迭代是否有效 | 是 |

主 KPI 在获得 2～4 周稳定基线前不设置固定目标。调用量、生成量和项目总数只作为规模背景，不能替代主 KPI。

### 1.3 指标分层

- 结果指标：NS-01、KPI-01～03。
- 驱动指标：阶段转化、周期、AI 成功率、采用方式、质量维度、知识命中与引用。
- 护栏指标：AI 失败率、P95 时延、重大错误率、阻断 Issue 密度、成本和事件数据质量。

## 2. 统一计算规则

- 默认统计单元为 `project_version_id`、`ai_task_id` 或 `optimization_id`，不得用原始点击数代替。
- 比率分母为 0 时返回 `N/A`，不返回 0%。
- 所有比率同时展示分子、分母和样本量；小样本不做趋势结论。
- 默认排除测试账号、内部压测、重复事件和已标记无效的数据。
- 时间采用事件发生时间；跨周期完成的项目版本分别提供“创建 cohort”和“完成时间”视图。
- 指标结果保存 `metric_id`、`metric_version`、计算时间、观察窗、过滤条件和数据质量状态。

## 8. MVP 首批指标

MVP 首批必须可计算：NS-01、KPI-01～03、PU-01～15、AR-02～09/11/12、AQ-01～08、VO-01～09。KA 系列只对 MVP 实际存在的预置知识来源记录 KA-05 所需明细，不建设完整知识指标看板。

首批看板不是 MVP 发布前提；可通过查询或离线报表验收，但业务记录、AI 追溯和采用反馈必须随功能开发同步落地。

## 9. 目标设置与复核

1. 上线前只设置数据质量门槛和安全/稳定性底线。
2. 上线后采集至少 2～4 周稳定基线，覆盖不同任务类型和完整项目版本。
3. 再为 NS-01、KPI-01～03 设置阶段目标，并记录目标依据、样本和信心等级。
4. 每月复核指标是否仍能驱动决策；无法改变行动的指标降级为诊断或移除。
5. 指标公式变化必须升级 `metric_version`，历史报表不得静默重算为新口径。
