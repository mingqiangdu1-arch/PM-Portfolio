# 信息架构

> 文档状态：当前有效
> 目标：把正式产品模块映射为用户可导航、可理解、可完成任务的页面结构

## 1. 一级导航

一级导航保持正式产品设计已确认的六个业务域，不新增“数据中心”“AI 能力中心”或“文件中心”：

1. **项目中心**：默认入口，包含项目列表、项目概览、项目版本和资料接续。
2. **产品设计**：Requirement、PRD、Flow、Design Review、Implementation Plan。
3. **实现确认**：实现资料、确认轮次、差异和验证就绪检查。
4. **产品验证**：Test Record、Issue、Bug/Optimization 扩展和迭代去向。
5. **知识中心**：Experience、Checklist、Skill、Prompt、Template；MVP 仅开放必要查看或后台预置能力。
6. **系统设置**：用户偏好、模型连接、基础模板、模块开关和审计入口。

文件选择、AI 任务、通知、上下文来源和操作审计作为跨模块能力，通过抽屉、弹窗或对象内入口出现，不占用一级导航。

## 2. 全局页面框架

```text
全局顶栏
├─ 产品名称 / 项目切换
├─ 当前项目与查看版本
├─ 全局任务中心（AI、解析、导出）
├─ 通知/待处理
└─ 用户菜单

一级侧栏
├─ 项目中心
├─ 产品设计
├─ 实现确认
├─ 产品验证
├─ 知识中心
└─ 系统设置

项目内上下文区
├─ 项目与版本上下文条
├─ 阶段导航
├─ 页面标题、状态摘要与主操作
└─ 页面内容 / 右侧上下文与追溯抽屉
```

未选择项目时，产品设计、实现确认和产品验证入口保留但提示先选择项目；知识中心和系统设置可独立进入。

## 4. 项目内局部导航

项目内页面采用“阶段导航 + 当前模块二级导航”：

- 阶段导航：需求 → PRD → Flow（可选）→ 设计评审 → 实现方案 → 实现确认 → 产品验证 → Issue 去向。
- 二级导航只展示当前业务域内对象，例如产品设计域展示需求、PRD、Flow、评审、实现方案。
- 阶段节点显示已完成、进行中、需处理、已跳过或不适用的用户摘要；不直接暴露数据库状态码。
- 点击已完成节点可查看；点击未到达节点时先展示前置条件，不允许无提示进入不可执行页面。

## 5. 页面归属规则

| 内容/动作 | 主责页面 | 不应出现为独立一级入口的原因 |
|---|---|---|
| 文件上传与版本 | 当前业务对象页的文件面板 | 文件是载体，不是业务事实 |
| AI 生成任务 | 当前工作台 + 全局任务中心 | AI 是支撑能力，不拥有业务状态 |
| 上下文来源 | AI 生成前配置与结果追溯抽屉 | 仅在任务决策时需要 |
| 数据反馈 | 对应业务页摘要卡/增强分析入口 | MVP 不建设独立分析工作台 |
| 版本比较 | 对象版本历史或项目版本管理 | 比较必须绑定具体版本类型 |
| 权限说明 | 动作附近和权限详情 | 权限服务于业务任务，不单独成为业务域 |

## 6. MVP 与增强页面边界

MVP 必须可用：PC-01～PC-08、PD-01～PD-05、PD-10～PD-15、IC-01～IC-06、PV-01～PV-05，以及必要的 SS-02/SS-03。Flow 页面 PD-06～PD-09 为可选能力，但一旦启用必须完整支持 Review 和版本保存。

KC 全量管理、复杂协作工作台、完整分析看板和高级 Flow 编辑属于增强功能。MVP 可以显示“尚未开放”说明或受控只读入口，但不得出现可以进入却无法完成任务的空壳主流程。

## 7. 命名与定位一致性

- 页面使用“项目版本”表示一轮产品迭代，使用“PRD 版本/Flow 版本/Plan 版本”表示产物版本。
- “查看版本”与“当前工作版本”始终分开表达。
- “评审通过”不等于“产物自动生效”；需要由有权用户确认保存的正式版本。
- “确认轮次”是不可变事实，不使用“覆盖确认”。
- Bug 与 Optimization 作为 Issue 类型扩展呈现，不与 Issue 并列为一级列表。
