# 页面结构设计

> 文档状态：当前有效
> 目标平台：桌面 Web 优先
> 保真度：低保真信息结构与交互注释
> 边界：不定义品牌、配色、字体、像素级规格、动效参数或前端实现

## 1. 通用页面骨架

```text
┌──────────────────────────────────────────────────────────────────────┐
│ [产品/项目切换] [当前查看版本 / 当前工作版本] [任务] [待处理] [用户] │
├──────────────┬───────────────────────────────────────────────────────┤
│ 一级导航      │ [项目与版本上下文条 / 只读历史提示]                   │
│ 项目中心      ├───────────────────────────────────────────────────────┤
│ 产品设计      │ [阶段导航：需求-PRD-Flow-评审-Plan-确认-验证-Issue]  │
│ 实现确认      ├───────────────────────────────────────────────────────┤
│ 产品验证      │ [页面标题] [状态摘要]              [主操作] [更多]    │
│ 知识中心      │ [下一步卡片 / 阻断与缺失提示]                         │
│ 系统设置      │                                                       │
│              │ [主内容区]                         [上下文/追溯抽屉]  │
└──────────────┴───────────────────────────────────────────────────────┘
```

### 通用组件清单

| 组件 | 内容 | 交互规则 |
|---|---|---|
| 项目/版本上下文条 | 项目、查看版本、当前工作版本、生命周期摘要 | 切换查看版本不改变当前工作版本；历史版本持续显示只读提示 |
| 阶段导航 | 核心业务节点及用户摘要 | 可查看已完成节点；未满足前置条件的节点先显示原因 |
| 下一步卡片 | 推荐动作、前置条件、阻断项、责任身份、产出 | 主操作始终与卡片一致；无权时显示申请/联系路径 |
| 页面主操作 | 当前页面唯一主要推进动作 | 危险或不可逆动作需影响确认；不与次要操作并列竞争 |
| 版本/追溯抽屉 | 来源版本、AI 能力版本、上下文来源、变更摘要 | 默认收起，需要审查时展开；历史记录只读 |
| 全局任务中心 | AI、文件解析、导出任务 | 可跨页面运行；完成后深链到目标对象审核页 |
| 反馈条 | 保存、失败、冲突、权限、数据质量 | 说明发生什么、影响什么、下一步是什么，不只显示错误码 |

## 2. PC-01 项目列表

### 页面目标

帮助用户快速进入最近项目、发现需要处理的项目版本，并创建或接续项目。

```text
┌────────────────────────────────────────────────────────────────┐
│ 项目中心                                      [新建项目]       │
│ [搜索] [状态筛选] [我的/全部] [排序]                            │
├────────────────────────────────────────────────────────────────┤
│ [最近项目]                                                      │
│ ┌ 项目卡：名称 / 当前工作版本 / 下一步 / 待处理 / 最近访问 ┐   │
│ └──────────────────────────────────────────────────────────┘   │
│ [全部项目表：项目 | 工作版本 | 当前节点 | 负责人 | 更新时间]   │
│ [分页/加载更多]                                                 │
└────────────────────────────────────────────────────────────────┘
```

| 组件 | 内容 | 操作 |
|---|---|---|
| 项目卡/行 | 名称、目标摘要、工作版本、节点、待处理数 | 打开 PC-03；更多菜单仅含归档等次要动作 |
| 新建项目 | 从零/已有资料的统一入口 | 进入 PC-02 |
| 筛选与搜索 | 状态、负责人、更新时间 | 空筛选结果提供清除筛选，不误导为“没有项目” |

## 3. PC-03 项目概览

### 页面目标

在一个页面回答：当前在哪个版本、已经完成什么、缺少什么、下一步做什么。

```text
┌────────────────────────────────────────────────────────────────┐
│ 项目名称 / 当前查看 Vx / 工作版本标记        [版本管理] [设置] │
│ [项目目标摘要] [资料完整性] [最近活动]                          │
├────────────────────────────────────────────────────────────────┤
│ [阶段导航....................................................] │
├───────────────────────────────┬────────────────────────────────┤
│ 下一步卡片                     │ 阻断/遗留清单                   │
│ 推荐动作 + 原因                │ 门禁缺失 / 风险接受 / 待处理    │
│ [继续当前任务]                 │ [查看全部]                      │
├───────────────────────────────┼────────────────────────────────┤
│ 当前版本产物摘要               │ 最近活动与责任人                │
│ Requirement/PRD/Flow/...       │ 创建、评审、确认、验证          │
└───────────────────────────────┴────────────────────────────────┘
```

数据反馈仅显示真实事实：当前阶段是否通过、阻断反馈数、确认轮次数、Issue 待处置数、AI 最近任务结果。未形成统计基线时不显示趋势判断。

## 4. PC-04 资料导入与起始节点确认

### 页面目标

保留原始资料并让用户确认资料类型、关联对象和接续节点。

```text
步骤 1 上传资料 → 步骤 2 解析与类型确认 → 步骤 3 起始节点 → 步骤 4 完整性确认

[上传区 / 已上传文件列表]
[解析建议：文件类型、可能对象、置信说明] [手动修改]
[可选起始节点 + 每个节点前置要求]
[完整性清单：已具备 / 待补充 / 已跳过 / 不适用]
[返回项目概览]                              [确认并进入目标节点]
```

解析失败时原文件仍出现在列表，状态为“需手动确认”；失败不清空用户已完成的其他步骤。

## 5. 产物工作台通用结构（PD-01、PD-03、PD-06、PD-13）

### 页面目标

在同一工作区完成来源查看、编辑、AI 生成、候选审核、版本保存和历史比较。

```text
┌────────────────────────────────────────────────────────────────────┐
│ [产物名称] [草稿/当前有效摘要] [版本历史]    [AI 生成] [保存/提交] │
├───────────────────┬──────────────────────────────┬─────────────────┤
│ 结构/章节导航      │ 编辑或候选审核主区            │ 依据与检查       │
│ - 当前章节         │ [正文/结构化表单]              │ 来源清单          │
│ - 待澄清项         │ [行内修改/评论定位]            │ 完整性检查        │
│ - 反馈定位         │ [候选与正式差异]               │ 重大错误提示      │
│                   │                              │ 追溯信息          │
├───────────────────┴──────────────────────────────┴─────────────────┤
│ [保存草稿] [拒绝候选] [修改后采用]                 [保存正式版本]   │
└────────────────────────────────────────────────────────────────────┘
```

### 组件清单

| 组件 | 内容 | 交互规则 |
|---|---|---|
| 章节/对象导航 | Requirement 项、PRD 章节、Flow 表达层、Plan 范围 | 展示缺失、反馈和未保存标记；不以颜色单独表达 |
| 编辑主区 | 结构化字段或 Markdown 内容 | 自动保存仅保存草稿；正式保存必须显式操作 |
| 来源面板 | Requirement、项目上下文、正式决策、文件版本 | 点击打开只读来源；无权来源显示不可访问而非泄露内容 |
| 检查结果 | 结构、完整性、追溯、安全、人工评价 | 重大错误阻止直接采用；一般提醒允许带理由继续 |
| 差异视图 | 候选与当前正式版本的新增/修改/删除 | 可逐段接受或编辑；不把候选自动合并 |
| 版本保存 | 版本号候选、变更摘要、来源版本 | 已评审内容修改总是新版本 |

### PD-01 需求工作台特有区域

- 原始输入固定只读保留。
- 待确认问题按“待确认、已确认、暂缓、不适用”分组。
- 用户确认结论与原始输入并列，不覆盖来源。
- 阻断待确认项未处理时，“进入 PRD”显示具体缺失。

### PD-03/04 PRD 工作台特有区域

- 章节导航至少覆盖目标、用户、范围、功能、业务规则、异常、权限和验收。
- 主 PRD 标记与补充 PRD 区分。
- 发起评审前展示版本冻结提示和未决项摘要。

### PD-06 Flow 工作台特有区域

- 顶部明确来源 PRD Version、主/子流程和生成范围。
- 工作区按“文本流程 → Mermaid → draw.io/导出”分层，不在同一步混合编辑。
- 文本 Review 未通过时，Mermaid 和导出层不可推进但可查看旧版本。
- 布局调整与业务逻辑调整在交互上分开标记；最终版本策略留待后续状态机阶段冻结。

### PD-13 Implementation Plan 特有区域

- 结构覆盖功能、规则、状态需求、异常、交互、依赖和验收范围。
- 已通过评审的 Plan 显示“进入实现确认”；未通过或版本已更新时说明需重新评审。

## 6. AI 生成配置与任务反馈

### 6.1 生成前面板

```text
┌──────────────────────── AI 生成配置 ──────────────────────────┐
│ 任务目标 / 产物类型                                           │
│ 所属项目版本 / 目标对象                                       │
│ 生成范围 / 来源版本 [查看来源]                                │
│ 用户补充要求                                                   │
│ 上下文预检：[已具备] [缺失] [不适用]                          │
│ Skill/模板/模型摘要 [高级设置（有权限）]                      │
│ 保存说明：结果先进入候选审核，不覆盖正式内容                  │
│ [取消] [保存配置]                               [开始生成]    │
└────────────────────────────────────────────────────────────────┘
```

### 6.2 生成中任务面板

```text
[任务名称] [运行中]
目标：项目 / 版本 / 对象
阶段：准备上下文 → 生成候选 → 质量检查 → 准备结果
已用时 / 最近更新时间
[可安全离开页面] [取消任务]
```

不显示无法验证的百分比。超出历史正常等待范围时显示“仍在运行，可继续等待或取消”，但不自动判定失败。

### 6.3 生成后候选审核

```text
候选结果 [质量检查摘要] [来源与追溯]
┌ 当前正式内容 ┐  ⇄  ┌ AI 候选/用户修改 ┐
[新增/修改/删除清单]
[拒绝] [修改输入并重新生成] [保存草稿] [修改后采用/直接采用]
```

采用结论必须记录：直接采用、轻微修改后采用、重大修改后采用或拒绝；拒绝/重大修改选择原因。`not_reviewed` 不作为采用结论。

```text
┌────────────────────────────────────────────────────────────────┐
│ 评审标题 / 引用版本 / 责任人 / 截止信息    [提交反馈/通过评审] │
├───────────────────────┬────────────────────────────────────────┤
│ 评审范围与版本快照     │ 反馈列表                               │
```

## 8. IC-01/03 实现确认

```text
┌────────────────────────────────────────────────────────────────┐
│ Implementation Plan + 当前有效确认轮次      [创建新确认轮次]  │
│ [历史轮次] [实际资料] [差异] [就绪检查]                         │
├────────────────────────────┬───────────────────────────────────┤
│ 实际实现证据                │ Difference 候选/已确认清单         │
│ 文件、截图、环境、外部引用   │ 原设计 / 实际 / 类型 / 原因 / 影响 │
│ [关联资料]                  │ [接受差异][要求处理][回写候选]     │
├────────────────────────────┴───────────────────────────────────┤
│ 验证就绪：页面/功能、接口、数据、环境、范围                     │
│ [保存草稿]                        [确认本轮/退回处理]            │
└────────────────────────────────────────────────────────────────┘
```

创建新轮次时复制引用而非覆盖历史事实。确认前展示将成为当前有效轮次的影响；存在阻断差异或就绪项未通过时禁止确认并提供定位入口。

## 9. PV-01/02 产品验证

```text
┌────────────────────────────────────────────────────────────────┐
│ 验证概览 / 关联确认轮次                     [创建 Test Record] │
│ [验证记录] [Issue] [版本去向摘要]                               │
├────────────────────────────────────────────────────────────────┤
│ Test Record 表单                                                │
│ 范围 / 环境 / 前置条件 / 步骤 / 预期 / 实际 / 证据              │
│ 结论：[通过][未通过][部分完成]                                  │
│ [保存草稿] [创建 Issue]                         [提交记录]      │
└────────────────────────────────────────────────────────────────┘
```

Test Record 固定显示关联的确认轮次，不允许改绑到其他轮次。提交后内容作为验证事实只读；补充或更正采用新记录或明确的更正机制，具体状态规则后续冻结。

## 10. PV-04/05 Issue 列表与详情

```text
Issue 列表：[搜索][类型][严重度][去向][状态] [新建 Issue]

Issue 详情
├─ 来源与证据（Test Record 可空，但 Project Version 必填）
├─ 类型：defect / feedback / data_anomaly / optimization
├─ 影响、严重度、优先级
├─ 类型扩展字段（Bug 或 Optimization）
├─ 处理讨论与责任人
└─ 去向：[当前版本修正][派生新版本][暂缓][拒绝]
```

选择“派生新版本”时先展示继承范围和不默认继承项；选择暂缓/拒绝必须填写理由。Issue 关闭后仍能查看来源和去向。

## 11. PC-06/07 版本管理与历史查看

```text
┌────────────────────────────────────────────────────────────────┐
│ 项目版本管理                               [派生新版本]        │
├──────────────────────────────┬─────────────────────────────────┤
│ 版本谱系                     │ 选中版本详情                     │
│ V1 ── V2 ── V3              │ 父版本 / 派生原因 / 生命周期     │
│       └── V2.1              │ 产物摘要 / Issue 来源 / 变更     │
│ [当前工作版本标记]            │ [只读查看][比较][基于此版本派生] │
└──────────────────────────────┴─────────────────────────────────┘
```

“设置当前工作版本”与“基于历史派生”分开，前者需要权限、审计和并发确认；后者创建新业务事实，不覆盖历史。

## 12. 数据反馈组件

| 场景 | 展示内容 | 限制 |
|---|---|---|
| 项目概览 | 阶段事实、周期摘要、阻断反馈、确认轮次、Issue 去向 | 不用文档生成量代表完成 |
| AI 任务 | 成功/失败、时延、采用结论、质量检查、来源 | Token/成本仅有可靠数据时展示 |
| 产物审核 | 完整度、追溯检查、重大错误、修改强度 | 自动检查不替代正确性判断 |
| 版本比较 | 分子、分母、样本量、绝对/相对变化、数据质量 | 无稳定基线或样本不足时不下改善结论 |
| 优化记录 | 主指标、驱动、护栏、观察窗、同期变更、结论 | 只允许改善/无变化/恶化/证据不足四类结论 |

## 13. 自适应与无障碍原则

- 桌面端优先支持复杂编辑与比较；较窄窗口将右侧面板收起为抽屉，主编辑区保持可用。
- 表格在窄窗口保留关键列，其余进入行详情，不以横向无限滚动作为唯一方案。
- 状态同时使用文字和图标，不以颜色单独表达。
- 键盘可访问阶段导航、列表、表单、对话框和候选差异；焦点顺序与视觉层级一致。
- 弹窗关闭后焦点返回触发元素；错误摘要可跳转到对应字段。
