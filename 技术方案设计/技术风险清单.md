# 技术风险清单

> 文档状态：当前有效
> 基线版本：V1.0
> 生效日期：2026-07-29
> 建立日期：2026-07-29
> 使用方式：每个 Sprint 开始复核触发信号，结束复核残余风险和关闭 Gate

## 1. 分级

- 概率：低/中/高。
- 影响：P0 阻断发布或存在不可恢复/安全风险；P1 阻断模块或关键路径；P2 可降级或延期。
- 状态：Open、Mitigating、Accepted、Closed。Accepted 必须有项目负责人、理由、期限和复核点；P0 不得仅以 Accepted 绕过。

## 3. 跨风险 Gate

### Sprint 0 前

- TR-02、03、04 的责任、契约和验证方法已进入任务。
- TR-18 给出可执行 Spike 样本与 pass/fail。
- 监控、Secret、备份和权限最小骨架有 owner。

### 进入业务 Sprint 前

- OpenAPI/事件/内部契约通过。
- MySQL 空库/升级迁移与表级授权通过。
- Web/API/AI/Worker/Redis/MinIO 在干净环境可启动。

### MVP 发布前

- 所有 P0 风险 Closed 或已有经确认且不违反“不可豁免项”的处置。
- RPO/RTO、故障降级、权限、追溯、迁移、文件和 Secret 测试通过。
- Flow 完整启用或安全关闭。
- CloudBase PoC 结果不替代生产方案评审。

## 5. 基线验收条件

- 覆盖架构、数据、AI、文件、缓存、权限、接口、部署、监控、团队和云端 PoC 风险。
- 每项风险都有触发信号、可执行预防、降级、DRI 与关闭 Gate。
- P0 风险不能通过隐藏功能、删除历史、降低审计或放宽追溯门槛规避。
- 风险清单与 Development Planning 的发布 Gate 和降级路径无冲突。
