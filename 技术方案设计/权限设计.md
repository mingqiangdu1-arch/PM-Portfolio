# 权限设计

> 文档状态：当前有效
> 基线版本：V1.0
> 生效日期：2026-07-29
> 建立日期：2026-07-29
> 范围：MVP 身份、项目角色、对象权限、内部服务身份与审计

## 1. 设计结论

MVP 使用“系统身份 + 固定项目角色 + 对象状态守卫”的授权模型，不建设组织、租户、动态策略引擎或审批链。

固定项目角色为 `owner`、`reviewer`、`implementer`、`tester`；系统角色为 `admin`。同一用户可兼任多个项目角色，普通动作取权限并集，但项目最终确认、产物正式化、工作版本切换、确认轮次生效和 Issue 去向仍要求 `owner`。`admin` 不自动获得项目内容最终确认权。

## 2. 身份与会话

### 2.1 登录凭据

- 邮箱规范化后唯一；登录失败不泄露邮箱是否存在。
- 密码使用 Argon2id；参数在 Sprint 0 依据目标服务器性能校准并版本化。
- 密码、Refresh Token、Provider Key 和内部服务 Secret 只保存哈希或 Secret 引用。
- 登录、刷新、退出、撤销、密码修改和异常重放均写审计。

### 2.2 Token

| Token | 载体 | 默认策略 | 撤销 |
|---|---|---|---|
| Access JWT | `Authorization: Bearer`，浏览器只保存在内存 | 短期；包含 user/session/jti，不含完整权限表 | 会话撤销或过期；关键写实时查权 |
| Refresh Token | Secure、HttpOnly、SameSite Cookie | 7 天；每次刷新轮换 | 哈希存储、退出/重放时整条 token family 撤销 |
| CSRF/Origin | 刷新/退出等 Cookie 命令 | 同源 Origin/Referer 校验；必要时双提交 Token | 校验失败拒绝 |
| Internal Service JWT | 内部 Authorization | 短期、固定 audience/scope/jti | Secret/Key 轮换、网络隔离 |

生产 Web 与 API 使用同源；CORS 默认拒绝，仅 Local/Staging 允许明确来源、方法和 Header。不得使用 `*` 搭配凭据。

## 3. 授权计算

一次业务动作按以下顺序判定：

1. 身份有效、会话未撤销。
2. 系统能力/功能旗标允许。
3. 用户是项目成员，或动作是允许的系统管理员动作。
4. 用户角色允许该动作。
5. 查看版本/工作版本、对象归属和状态允许。
6. 历史、已确认或不可变事实未被原位修改。
7. `expected_version` 与最新版本一致。
8. 目标引用、文件关系和 AI 候选仍有效。

任一步失败即拒绝；前端隐藏按钮不能代替后端授权。

## 4. 项目角色动作矩阵

符号：`R` 查看，`C` 创建，`U` 编辑草稿，`S` 提交事实/反馈，`F` 最终确认/正式化，`M` 管理。

| 资源/动作 | owner | reviewer | implementer | tester | admin |
|---|---|---|---|---|---|
| 项目与上下文查看 | R | R | R | R | 仅获项目成员身份后 R |
| 创建项目/V1 | C/F | — | — | — | 可创建自己的项目 |
| 项目成员/固定角色 | M | — | — | — | 系统支持，不替 owner 决策 |
| 归档/恢复项目 | F | — | — | — | 系统运维仅在授权流程下 |
| 查看历史/谱系 | R | R | R | R | 项目成员规则 |
| 设置工作版本 | F | — | — | — | — |
| 派生项目版本 | F | — | — | — | — |
| 文件上传/关联草稿 | C/U | C（评审证据） | C（实现证据） | C（测试证据） | 无项目权限则禁止 |
| Requirement 草稿 | C/U/F | R/S 建议 | R | R | — |
| PRD/Flow/Plan 草稿 | C/U/F | R/S 反馈 | R/S 实现说明 | R | — |
| 发起 Review | F | R | R | R | — |
| 提交 Review Feedback | C/S | C/S | C/S（相关范围） | C/S（相关范围） | — |
| 处置反馈/Review 结论 | F | S 建议 | S 建议 | S 建议 | — |
| AI Task 发起 | C | C（允许任务） | C（允许任务） | C（允许任务） | 仅管理测试任务 |
| AI 候选采用/正式化 | F | — | — | — | — |
| Confirmation 草稿/证据 | C/U/F | R/S | C/U/S | R/S | — |
| Confirmation 生效 | F | — | S 提交就绪 | S 提交验证建议 | — |
| Test Record 草稿/提交 | C/U/F | R | R/S 证据 | C/U/S | — |
| Issue 创建 | C/S | C/S | C/S | C/S | — |
| Issue 去向/关闭/派生版本 | F | S 建议 | S 建议 | S 建议 | — |
| Provider/Profile/Flag | — | — | — | — | M |
| Skill/Prompt/Template 发布 | — | — | — | — | M；MVP 仅预置受控版本 |

`admin` 的系统配置权与项目业务权分离；紧急运维访问必须有显式项目授权或独立受审计的 break-glass 流程，MVP 默认不开启 break-glass。

## 5. 对象与版本规则

- 所有项目内对象先校验 `project_id` 和 `project_version_id`，禁止只凭对象 ID 授权。
- 查看历史版本允许 R，但任何推进动作只能作用于符合规则的工作版本。
- 已评审/正式/确认/提交事实只读；修改必须创建新产物版本、确认轮次、Test 更正事实或派生项目版本。
- 文件授权由“项目成员 + 关联业务对象 + file_version”共同决定；知道对象键不能获得权限。
- AI Task 权限由发起时用户、项目、目标对象和任务类型冻结；查询/取消仍实时校验当前成员关系。
- 用户失去权限后，不再可读取候选正文或下载文件；历史审计保留操作者 ID。

## 6. 防枚举与响应

| 场景 | 响应策略 |
|---|---|
| 未登录 | 401 `AUTH_REQUIRED` |
| 已登录但不是项目成员，且对象存在性敏感 | 404 `RESOURCE_NOT_FOUND` |
| 已知项目内角色不足 | 403 `FORBIDDEN`，可返回所需角色摘要 |
| 历史对象禁止编辑 | 409 `HISTORICAL_READ_ONLY` |
| 功能旗标关闭 | 404 或 409 `FEATURE_DISABLED`，不得只隐藏 UI |
| 关键权限已变化 | 403 `PERMISSION_CHANGED`，原事务不提交 |

错误 `details` 不返回其他成员、对象正文、内部 ID、对象存储键或策略实现细节。

## 7. 关键命令权限

关键命令包括：

- 设置工作版本、派生版本。
- Requirement/PRD/Flow/Plan 正式化。
- Review 通过/退回。
- Confirmation 生效。
- Test Record 提交。
- Issue 去向与关闭。
- Provider、模型、功能旗标和能力版本发布。

要求：

- 不使用超过 60 秒的权限缓存结果。
- 在事务写入前再次校验权限和对象版本。
- 写 `actor_user_id`、实际角色集合、operation、object、result、reason、trace/command ID。
- 幂等重放返回原结果，不重复写业务事实；不同请求体不得复用 Key。

## 8. 内部服务权限

### 8.1 服务身份

| 调用方 | 被调用方 | Scope |
|---|---|---|
| Business API | AI API | `ai.task:create/read/cancel`、health |
| AI Worker | Business API | `context:read`、`file:read-signed`，限定 task |
| Event Consumer | MySQL/Outbox | 只读 Outbox、写行为事件/拒收 |
| Metric Job | MySQL | 只读权威事实、写指标/质量表 |
| Monitoring | 服务 metrics/health | 只读，无业务正文 |

- Internal JWT 包含 `iss/sub/aud/scope/jti/iat/exp` 和必要 task/trace 约束。
- 内部服务身份不能冒充最终用户，也不能绕过 Business API 正式化。
- Worker 拉取 Context 时，Business API 根据 Task 冻结用户与当前项目权限重新判断，不信任 Worker 自报 scope。
- 服务账号使用独立 DB 用户；表级权限与《数据库详细设计》的写入责任一致。

## 9. 文件与敏感信息

- 上传前校验扩展名、声明 MIME、大小；完成时以服务端检测与校验和为准。
- 签名 URL 短期、单方法、单对象；下载 URL 不进入日志和长期事件。
- Provider Key、JWT Secret、DB/S3 密码只由运行时 Secret 注入。
- Prompt、Context、文件正文和未采用 AI 结果默认不得进入日志、事件或错误响应。
- 导出、下载和 Provider 配置读取均需审计；审计只保存摘要/指纹，不保存 Secret。

## 10. 缓存与权限变化

- `authz:{env}:{user_id}:{project_id}` 只缓存非关键只读摘要，TTL 最长 60 秒。
- 成员角色变更、项目归档、会话撤销和权限版本变化必须主动删除缓存。
- 关键写操作查询 MySQL 最新成员与对象状态。
- 已建立 SSE 连接在权限变化后，下一次心跳或事件发送前重新校验；失权后关闭且不再发送正文。
- 已排队 AI Task 若发起者失权，在 Worker Precheck/正式化 Gate 进入 blocked/stale，不继续扩大数据访问。

## 11. 审计要求

必须审计：

- 登录、刷新重放、退出和会话撤销。
- 项目/成员/角色、工作版本、归档/恢复和派生。
- 文件上传完成、下载签发、关联和归档。
- AI Task 创建/取消/重试、Provider 配置、正式化与拒绝。
- Review、Confirmation、Test、Issue 去向。
- 功能旗标、Prompt/Template/Skill/Model 发布。

审计失败时，关键业务命令回滚；普通读取日志失败不阻断读取，但必须触发监控。

## 12. 安全测试

- 每个端点覆盖无 Token、过期 Token、撤销 Token、非成员、错误角色、多角色和 admin 非项目成员。
- 覆盖水平越权：替换 project/object/file/task ID。
- 覆盖历史只读、工作版本变化、权限在请求期间变化和 `expected_version` 冲突。
- 覆盖 Refresh Token 轮换、重放、Cookie 属性、Origin/CSRF 和 CORS。
- 覆盖内部接口公网不可达、错误 audience/scope、过期服务 JWT 和 task scope 越权。
- 覆盖签名 URL 过期、改方法、改对象、重复使用和下载越权。

## 13. 验收条件

- 固定角色矩阵能映射到全部 MVP 业务动作且无默认放行。
- owner 最终确认权、admin 系统配置权和项目内容权限明确分离。
- 关键写操作具备实时权限、幂等、并发、审计和历史保护。
- 内部 AI/数据服务不能直接写正式业务状态。
- 权限错误不泄露对象存在性、正文、Secret 或内部实现。

本文已于 2026-07-29 通过用户确认，构成当前有效 V1.0 权限设计基线。Sprint 0 的认证、授权与内部服务身份实现必须覆盖本文矩阵和安全测试，不得用前端隐藏或静态 JWT 权限替代服务端实时门禁。
