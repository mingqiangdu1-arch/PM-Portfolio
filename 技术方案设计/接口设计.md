# 接口设计

> 文档状态：当前有效
> 基线版本：V1.0
> 生效日期：2026-07-29
> 建立日期：2026-07-29
> 契约范围：MVP 公共 REST/SSE 与 Business API—AI Service 内部接口
> 后续产物：Sprint 0 将本文转换为 OpenAPI 3.1、JSON Schema、生成 Client 和契约测试

## 1. 接口结论

- Browser 只访问 Business API `/api/v1`。
- AI API 与 Business API 的内部接口使用 `/internal/v1`，仅在容器内部网络开放。
- OpenAPI 是 Sprint 0 后的字段级机器事实源；本文是生成 OpenAPI 前的人工确认基线。
- ID 对外全部为十进制字符串或明确的 public UUID；时间为 UTC RFC 3339。
- 所有关键写命令使用 `Idempotency-Key`；可变对象提交 `expected_version`。
- 前端通过 SSE 获取任务状态，断线后使用 `Last-Event-ID` 重连或查询任务快照。

## 2. 公共协议

### 2.1 Header

| Header | 方向 | 必需 | 规则 |
|---|---|---:|---|
| `Authorization: Bearer <access>` | Client→API | 登录后 | 短期 Access JWT |
| `Idempotency-Key` | Client→API | 创建/关键命令 | 1～128 字符；同用户+端点隔离 |
| `X-Request-ID` | Client→API | 否 | 合法时沿用，否则服务端生成 |
| `If-None-Match` | Client→API | 否 | 只读详情缓存；不得用于写并发 |
| `Last-Event-ID` | Client→SSE | 重连时 | 从该事件之后续传 |
| `X-Trace-ID` | API→Client | 是 | 同响应体 `trace_id` |
| `Retry-After` | API→Client | 429/部分 503 | 秒或 HTTP date |

### 2.2 成功与错误信封

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "trace_id": "trc_..."
}
```

```json
{
  "code": "VERSION_CONFLICT",
  "message": "内容已被更新，请比较最新版本后继续。",
  "details": {
    "field_errors": [],
    "latest_version": 8,
    "latest_object_version_id": "123"
  },
  "trace_id": "trc_..."
}
```

`details` 只包含可安全展示的字段错误、缺失项、最新版本引用和恢复动作；不得包含堆栈、SQL、对象存储键、Prompt/Context 正文或 Secret。

### 2.3 公共类型

| 类型 | 字段 |
|---|---|
| `CursorPage<T>` | `items:T[]`、`next_cursor:string|null`、`has_more:boolean` |
| `ObjectRef` | `object_type:string`、`object_id:string`、`object_version_id:string|null` |
| `VersionRef` | `id:string`、`version_no:string`、`status:string`、`content_hash:string`、`created_at:string` |
| `ActorSummary` | `user_id:string`、`display_name:string` |
| `PermissionSummary` | `roles:string[]`、`allowed_actions:string[]`、`permission_version:number` |
| `SourceRef` | `source_type`、`source_id`、`source_version_id`、`content_hash`、`label` |
| `TraceSummary` | `trace_id`、`command_id|null`、`created_at` |

游标由服务端签名或编码排序键，客户端不得解析。默认按 `created_at DESC,id DESC`；稳定列表必须使用唯一尾键。

### 2.4 写入语义

- `POST` 创建资源或命令；命令路径使用动词子资源，例如 `:confirm`。
- `PATCH` 只用于草稿或明确可变元数据，必须提交 `expected_version`。
- 已确认/已提交/历史事实不提供正文 PATCH。
- 幂等记录绑定 user、endpoint、key、request hash；同 Key 不同请求体返回 409 `IDEMPOTENCY_CONFLICT`。
- 业务写成功、审计和 Outbox 同事务；事件消费者失败不回滚业务事实。

## 3. 身份与会话

| 方法与路径 | 权限 | 请求字段 | 响应 `data` | 关键错误 |
|---|---|---|---|---|
| `POST /api/v1/auth/register` | 匿名 | `email`、`password`、`display_name` | `user`、`access_token`、`expires_in`；设置 Refresh Cookie | `EMAIL_EXISTS`、`WEAK_PASSWORD` |
| `POST /api/v1/auth/login` | 匿名 | `email`、`password` | `user`、`access_token`、`expires_in`；设置 Refresh Cookie | `INVALID_CREDENTIALS`、`RATE_LIMITED` |
| `POST /api/v1/auth/refresh` | Refresh Cookie | 无正文或 `csrf_token` | 新 `access_token`、`expires_in`；轮换 Cookie | `REFRESH_INVALID`、`TOKEN_REUSE_DETECTED` |
| `POST /api/v1/auth/logout` | 登录/Refresh | 无 | `logged_out:true` | — |
| `GET /api/v1/session` | 登录 | 无 | `user`、`system_roles`、`session_id`、`expires_at` | `AUTH_REQUIRED` |
| `GET /api/v1/users/me/preferences` | 登录 | 无 | `timezone`、`locale`、`ui_preferences`、`version` | — |
| `PATCH /api/v1/users/me/preferences` | 登录 | `timezone?`、`locale?`、`ui_preferences?`、`expected_version` | 更新后 preferences | `VERSION_CONFLICT` |

注册、登录、刷新、退出写 `operation_audit_log`；失败不记录密码或邮箱原文到普通日志。

## 5. 文件与解析

### 5.1 初始化上传

`POST /api/v1/files/uploads`，项目成员且角色允许上传，必须幂等。

请求：

| 字段 | 类型 | 必需 | 规则 |
|---|---|---:|---|
| `project_id` | string | 是 | 当前项目 |
| `logical_name` | string | 是 | 1～255；不作为对象键 |
| `size_bytes` | integer | 是 | 1～52,428,800 |
| `mime_type` | string | 是 | 声明值，完成时复核 |
| `extension` | string | 否 | 规范化 |
| `checksum_sha256` | string | 是 | 64 hex |
| `relation` | object|null | 否 | `object_type/id/version_id/relation_type` |

响应：`upload_id,stored_file_id,pending_file_version_id,upload_url,http_method,required_headers,expires_at,max_size_bytes`。`upload_url` 为敏感短期值，不进入日志。

### 5.2 完成与读取

| 方法与路径 | 权限 | 请求字段 | 响应 |
|---|---|---|---|
| `POST /api/v1/files/uploads/{upload_id}:complete` | 发起者/owner；幂等 | `etag?`、`checksum_sha256`、`expected_file_version?` | file、file_version、relation、storage_status |
| `POST /api/v1/files/uploads/{upload_id}:abort` | 发起者/owner；幂等 | `reason` | `aborted:true` |

### 11.3 采用与正式化

`POST /api/v1/ai/results/{result_id}:formalize`，owner，必须幂等。

请求：`adoption:adopt/modified_adopt/reject`、`target_object_type`、`target_object_id`、`target_snapshot_hash`、`expected_version`、`modified_content_json?`、`reason?`。

规则：

- `adopt` 使用候选内容；`modified_adopt` 必须提交修改内容；`reject` 不创建正式领域版本。
- 重新验证追溯完整、Result ready、用户权限、目标快照和并发版本。
- 成功响应返回 `adoption_id` 与正式 `artifact_version_ref`；失败不改变旧正式版本。

## 12. SSE 协议

Endpoint：`GET /api/v1/ai/tasks/{task_id}/events`，`Content-Type: text/event-stream`。

事件：

```text
id: 42
event: task.status
data: {"task_id":"...","status":"generating","stage":"provider_call","occurred_at":"...","trace_id":"..."}
```

| 事件 | data 必含 |
|---|---|
| `task.snapshot` | task_id、status、last_event_id、occurred_at |
| `task.status` | task_id、status、stage、occurred_at、trace_id |
| `task.warning` | warning_code、message、recoverable |
| `task.result` | result_id、status、quality_summary、target_snapshot_hash |
| `task.terminal` | status、failure_code?、finished_at |
| `heartbeat` | server_time |

规则：

- 单 Task 的 `id` 单调递增；重连携带 `Last-Event-ID`。
- 无法续传时先发送最新 `task.snapshot`，不得伪造丢失事件。
- 心跳建议 15 秒；代理空闲超时必须大于两个心跳周期。
- SSE 不传 Prompt、Context/候选全文或签名 URL。
- 断线不取消 Task；客户端失败后轮询 `GET /ai/tasks/{id}`。

## 13. 内部 AI 接口

内部请求使用短期 Service JWT、`X-Trace-ID`、`X-Command-ID`；不经公共反向代理。

### 13.1 Task

| 方法与路径 | 调用方 | 请求 | 响应 |
|---|---|---|---|
| `POST /internal/v1/ai/tasks` | Business API | Task Envelope | task public id、status、accepted_at |
| `GET /internal/v1/ai/tasks/{id}` | Business API | 无 | 权威运行摘要、result refs |
| `POST /internal/v1/ai/tasks/{id}:cancel` | Business API | reason、actor/command ref | cancel status |
| `GET /internal/v1/ai/health/ready` | Business API/monitor | 无 | dependency summary |

Task Envelope：

`task_public_id,user_id,project_id,project_version_id,module,task_type,target:ObjectRef,target_snapshot_hash,source_ref_ids[],capability_selection,risk_acceptances,command_id,trace_id,requested_at`。

正文、文件字节、Secret 不进入 Envelope。

### 13.2 Context

| 方法与路径 | 调用方 | 请求/响应 |
|---|---|---|
| `POST /internal/v1/ai/tasks/{id}/context-snapshot` | AI Worker | `requested_source_refs[],token_budget` → 权限过滤后的内容引用/摘要/hash |
| `POST /internal/v1/ai/tasks/{id}/file-access` | AI Worker | `file_version_ids[]` → 限 task 的短期读取 URL |
| `POST /internal/v1/ai/tasks/{id}/target-freshness` | AI Worker | target hash → `fresh:boolean,latest_ref?` |

Business API 根据 Task 冻结用户和当前权限校验；Worker 不能扩大 source scope。

## 16. 契约兼容与开发并行

- 同一 `/api/v1` 允许增加可选响应字段、可选请求字段和新 Endpoint。
- 删除/重命名字段、改变类型/必填性、收窄枚举或改变语义属于破坏性变更，需新版本或迁移窗口。
- Contract PR 先于实现 PR；前端生成 Client 和 Mock，AI 服务生成内部 Consumer Stub。
- 契约包含成功、权限、校验、冲突、依赖失败和恢复示例。
- OpenAPI/Schema hash 进入构建与发布元数据，运行版本不匹配时阻断部署。

## 17. 契约测试与验收

- 每个 Endpoint 验证身份、角色、字段、错误信封、ID/time 序列化。
- 所有创建/命令测试同 Key 同正文、同 Key 不同正文和超时后重放。
- 所有可变对象测试 `expected_version` 成功、缺失和冲突。

- 接口与《数据字典》《权限设计》《页面状态机》《数据埋点设计》逐项可追踪。
